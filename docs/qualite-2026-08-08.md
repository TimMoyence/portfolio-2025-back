# Qualite outillee — etat verrouille au 2026-08-08

Remplace `qualite-baseline-2026-08-07.md`, qui decrivait une dette mesuree mais non
bloquante. Les quatre outils sont desormais branches dans `ci:check`, dans
`pre-push:check` et dans le workflow GitHub, tous en echec bloquant.

## Comment lancer chaque outil

```bash
pnpm run lint                # ESLint + eslint-plugin-sonarjs, --max-warnings=0
pnpm run quality:cpd         # duplication du code de production
pnpm run quality:cpd:tests   # duplication dans les suites de tests
pnpm run quality:knip        # fichiers / exports / dependances non utilises
pnpm run guard:comments      # commentaires narratifs sans fait verifiable
```

Si l un de ces scripts se termine par un SIGABRT, c est le wrapper `rtk` et non le
projet : relancer en prefixant par `rtk proxy`.

## 1. sonarjs — la dette n etait pas dans le comptage

Le chiffre de 238 violations ne mesurait pas ce qu il semblait mesurer. `pnpm run lint`
n en voyait aucune : **28 regles `sonarjs` etaient explicitement desactivees** dans
`eslint.config.mjs`, et `sonarjs/cognitive-complexity` tournait en cliquet cale sur
**51** — le pire cas de l epoque, contre un defaut sonar de 15. Les 238 violations
n etaient visibles que via une seconde configuration, `eslint.sonar-full.config.mjs`,
qui ne bloquait rien.

Etat actuel :

- les 28 desactivations sont supprimees, `sonarjs/recommended` est integralement en
  `error` ;
- `cognitive-complexity` est revenu au defaut de la regle (15) ;
- `--max-warnings=0` est pose sur `lint` : une directive `eslint-disable` devenue
  inutile echoue au meme titre qu une violation, ce qui empeche de reintroduire une
  regle desactivee sans que la CI le voie ;
- `eslint.sonar-full.config.mjs` et le script `quality:sonar` sont **supprimes** : ils
  n existaient que pour mesurer les regles neutralisees, il n y en a plus.

Les desactivations restantes sont ciblees a la ligne et justifiees sur place. Elles
concernent des fixtures de test (`no-hardcoded-ip`, `no-hardcoded-passwords` sur des
IP et mots de passe de test) et des contraintes d environnement verifiables.

## 2. jscpd — duplication

Le code de production etait a 2,03 % pour un seuil de 2 % : la CI aurait echoue des le
branchement. Les trois clones nommes dans le rapport etaient tous dans
`src/modules/weather/` — auto-duplication de `WeatherUserPreferences.ts` sur la
validation des unites, et bloc de mapping partage entre `OpenMeteoProxy.service.ts` et
`OpenWeatherMapProxy.service.ts`.

La duplication des **suites de tests** a ete traitee separement. Elle melangeait deux
natures qu il faut distinguer :

- de la **duplication de mocks entre fichiers** — un mock d `ExecutionContext` etait
  copie-colle entre `jwt-auth.guard.spec.ts` et `roles.guard.spec.ts`, entre autres.
  C est une violation directe de la regle du `CLAUDE.md` (« ne jamais dupliquer les mocks
  dans chaque fichier `.spec.ts` ») : elle se resout par extraction en factory partagee
  dans `test/factories/` ;
- de la **repetition interne a un fichier** (meme bloc arrange/act dans plusieurs `it`),
  qui se resout par un helper local ou `it.each`.

Ce qui subsiste apres traitement est ce dont la factorisation nuirait a la lisibilite du
test — un test doit rester comprehensible seul, sans naviguer dans trois fichiers. Le
seuil est cale sur ce residuel et fait cliquet : la duplication des tests ne peut plus
croitre.

## 4. Commentaires narratifs

Plafond `"guard-no-comments".maxOffenses` pose a **0**. Le cliquet ne remonte jamais :
tout commentaire narratif ajoute fait echouer `ci:check`, `pre-push:check` et la CI.

Sur les 376 violations de depart, 32 etaient du code commente — supprime. Le reste
etait de la prose : supprimee quand l information est redecouvrable en lisant le code,
reecrite avec son ancre verifiable quand elle portait une contrainte externe reelle
(RFC, CVE, nom et version de dependance, date de mesure, nom de fichier).

`gitleaks:allow` a ete ajoute aux directives exemptees de
`scripts/lib/comment-doctrine.mjs`, avec son test. `gitleaks` est reellement actif dans
`.github/workflows/ci.yml` via `gitleaks-action` : c est une directive d outil au meme
titre qu `istanbul ignore`, pas de la narration.

## Perimetre du garde de commentaires

`scripts/lib/comment-scope.mjs` limite l inspection aux extensions source, style et
markup, sous `src/`, `test/`, `scripts/` et a la racine du depot. Les fichiers `.md`,
`.json`, `.jsonc` et `.yml` — dont `knip.jsonc` et les workflows GitHub — sont hors
perimetre : leurs commentaires ne sont pas comptes.
